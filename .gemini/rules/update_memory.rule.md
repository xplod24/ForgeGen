# Memory Maintenance Rule

- **Always Check for MEMORY.md:** When working in a project workspace, always check if a `MEMORY.md` (or similar project memory file) exists in the project root.
- **Proactive Updates:** Whenever you complete a task that involves significant code changes, major refactors, or architectural decisions, you MUST update the `MEMORY.md` file to reflect these changes.
- **What to Record:** Ensure that any newly established UI constraints, architectural patterns, deprecated mechanisms, or pending tasks are properly documented in the file.
- **Don't wait for permission:** You should update this file as part of the natural conclusion of a major task, without requiring explicit user prompting.
